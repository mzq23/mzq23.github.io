hugo文章上传步骤

从新建文章到推送上线的完整流程，以及 push 失败的排查方法

2025-08-16 in 教程, 总结 | Tags: Github, Cmd, Markdown

这篇文章最早记录的是手动敲命令发布的老流程。现在简单很多：把 .md 丢进 _inbox/<分类名>/（仓库根目录下，不在 content/ 里），然后双击「发布博客.bat」就行 —— 标题、日期、描述、分类、slug 都会自动补齐，分类就是文件夹名。

下面把手动流程和故障排查保留下来，日后出问题时可以对照。

生成文章

在 dev 文件夹下打开 cmd，输入下面指令：

hugo new content post/新文章名/index.md

注意中英文输入法切换 —— 打成中文标点的话，frontmatter 会解析失败。

编辑文章

title = "标题"

description = "描述"

date = '时间'

draft = true

categories = [
    "类别",
    ]

tags = [
    "标签",
     ]

image = "图片名称（带后缀）"

push 到 github

在 dev 文件夹下打开 cmd，输入下面指令：

git add .
git commit -m "update"
git push

分号可以在一行里串起多条指令，但可读性差，不太推荐：

git add . ; git commit -m "update" ; git push

push 失败：代理问题

原因 1：VPN 代理导致本地网络异常。（笔者采用此法解决）

如果你开着 VPN，很可能就是代理的问题，这时候设置一下 http.proxy 就可以了。 一定要先查看自己的 VPN 端口号，假如端口号是 7890，在 git bash 命令行中输入：

git config --global http.proxy 127.0.0.1:7890
git config --global https.proxy 127.0.0.1:7890

反过来，如果 VPN 已经关掉、但 git 里还留着代理配置，也会连不上，这时把它取消掉：

# 首先，查一下当前全局的 http 代理
git config --global http.proxy
# 如果有代理，就取消
git config --global --unset http.proxy

# 再查 https 的代理
git config --global https.proxy
# 同样的，有就取消
git config --global --unset https.proxy
